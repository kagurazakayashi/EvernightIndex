# EvernightIndex

[English](README.md) | [简体中文](README.zh-CN.md) | [繁體中文](README.zh-TW.md) | [日本語](README.ja-JP.md)

EvernightIndex は Go で実装した Windows / macOS / Linux 向けのコマンドラインツールです。1 つのディレクトリツリーの SQLite 索引を保持し、属性と名前の検索、変更ログ、索引済みの 2 ディレクトリ間の重複検出に答えます。利用者のファイルを削除・移動・ハードリンク化することはありません。

本ページは日本語版です。構成とバージョンは英語の主文書と同期しています。

## 現在の状態

- バージョン `0.1.0-dev`（プロジェクトの骨組みに保存層と実行制御層を追加）。コマンド契約、4 言語のメッセージ資源、SQLite の基盤、schema バージョン 2、ステージングと公開世代、プロセス間の書き込みロック、実行ライフサイクル、毎秒統計が揃っています。
- `info` は読み取り専用コマンドとして実装済みです。形式バージョン、データベース UUID、束縛されたルート、公開済み世代、項目とダイジェストの網羅率、直近の実行、未出力の変更ログを報告します。データベースの作成・移行・ロックは行いません。
- 走査とメタデータのモジュール（`internal/scan`、`internal/fsmeta`）と共通パターン照合（`internal/match`）は実装済みで、Windows 上で実際のテストにより検証しています。ただし呼び出すコマンドはまだないため、このビルドではコマンドラインからディレクトリを走査することはできません。実際の挙動は下記「スキャンとメタデータ収集」を参照してください。
- それ以外の業務コマンド（`index`、`find`、`dupes`、`export-log`、`recover`）は引数の解析と検証だけを行い、終了コード `1` と `E_NOT_IMPLEMENTED` で失敗します。走査処理の `index` への接続、SHA256 計算、変更ログ CSV、検索、重複検出、一時作業コピーと復旧は**未実装**です。以下の章は固定済みの契約を示すもので、利用可能な機能ではありません。

## 動作要件

- ビルドには Go `1.26.0` 以降が必要です（SQLite ドライバの下限）。本ステップでは `go1.26.5 windows/amd64` でビルドとテストを実施しました。
- CGO と C コンパイラは不要です。`CGO_ENABLED=0` で Windows / macOS / Linux をビルドできます。
- 実行時に必要なのはデータベースを置ける書き込み可能な場所だけです。既定のデータベースパスは `<ルート>/index.db` です。

## ビルドとテスト

```sh
git clone https://github.com/kagurazakayashi/EvernightIndex.git
cd EvernightIndex
go build ./cmd/evernightindex
go test ./...
```

バージョン情報の注入:

```sh
go build -ldflags "-X main.version=0.1.0 -X main.commit=$(git rev-parse --short HEAD) -X main.buildDate=2026-11-11" ./cmd/evernightindex
```

クロスコンパイル（3 対象とも `CGO_ENABLED=0`）:

```sh
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build ./cmd/evernightindex
CGO_ENABLED=0 GOOS=darwin  GOARCH=arm64 go build ./cmd/evernightindex
CGO_ENABLED=0 GOOS=linux   GOARCH=amd64 go build ./cmd/evernightindex
```

Windows PowerShell では先に `$env:CGO_ENABLED="0"` と `$env:GOOS="windows"` を設定してから同じ `go build` を実行します。

`scripts/verify.sh` は書式検査、vet、テスト、4 対象のクロスビルドをまとめて実行します（`JOBS`、`GOMAXPROCS`、`OUT` で並列度と出力先を制限できます）。

## クイックスタート

```sh
evernightindex --version
evernightindex --help
evernightindex index --help
evernightindex --lang ja-JP --help
evernightindex index /data --help
evernightindex info --db /data/index.db
```

`cmd` では空白を含むパスを二重引用符で囲みます（`--db "C:\\my data\\index.db"`）。PowerShell では単一引用符が簡単です。`info` は既存のデータベースを読み取り専用で開きます。`--db` がない場合は終了コード `2` で失敗し、データベースが存在しない、他プログラム製、破損、より新しいバージョン、未完成の索引の場合は安定したエラーコードで拒否し、ファイルを変更しません。`--help` を付けずに `index /data` を実行すると、現状は終了コード `1` で失敗し、何も読み書きしません。

## 言語

優先順位: `--lang`/`-l` > `EVERNIGHTINDEX_LANG` > システム言語 > 英語。

- Windows: ユーザーインターフェース言語（BCP47、例 `zh-TW`）。
- macOS: `defaults read -g AppleLocale`。
- Linux とその他の Unix: `LC_ALL`、`LC_MESSAGES`、`LANG` の順。`C`/`POSIX` は「未指定」とみなし英語に戻します。

| タグ | 別名 |
| --- | --- |
| `zh-CN` | `zh`、`zh_CN`、`zh-Hans`、`zh-SG` |
| `zh-TW` | `zh_TW`、`zh-Hant`、`zh-Hant-TW`、`zh-HK`、`zh-MO` |
| `en-US` | `en`、`en_US`、`en-GB` |
| `ja-JP` | `ja`、`ja_JP` |
| `auto` | 環境から自動判定 |

明示された不正な値はエラー（`E_INVALID_LANGUAGE`）であり、暗黙に他の言語へ置き換えません。機械的な項目（オプション名、コマンド名、列挙値、エラーコード、CSV 見出し、JSONL のキー、数値）は翻訳せず、人間向けの文だけを翻訳します。欠けた項目は英語に戻し、4 言語の欠落キーとプレースホルダーの一致はテストで検査します。

## 出力ストリーム

- 標準出力は結果のみ: 検索結果の行、重複グループ、`info` のレポート、明示的に要求された構造化出力。
- 標準エラーは進捗、警告、エラー、パスごとの詳細記録、統計。
- 実行中は 1 秒ごとに統計を標準エラーへ出力します。1 秒未満で終わる実行でも最終集計を出力するため、処理済み・失敗・エラーイベント・公開済みの件数は常に確認できます。統計は検出・処理済み・成功・失敗・エラーイベント・公開済みを分けて数えます。処理済みは保存済みではなく、キャンセルやロールバックの後は公開済みが 0 のままです。
- `--quiet` は通常の進捗**と**最終集計を止め（エラーは決して隠しません）、`--verbose` はパスごとの記録を追加し、`--progress=false` は毎秒の出力だけを止めて最終集計は残します。`--quiet` と `--verbose` の同時指定は拒否されます。

## データベース基盤

- ドライバ: `modernc.org/sqlite v1.62.0`（純 Go、CGO 不要）。選定は「純 Go」というラベルではなく、トランザクション、キャンセル、一貫性バックアップ、クロスコンパイルを実測した結果です。
- 接続: プロセスごとに 1 接続のプール、WAL、`busy_timeout`、`foreign_keys=1`、`synchronous=NORMAL`。
- 識別とバージョン: `PRAGMA application_id = 0x45564E49`（"EVNI"）、`PRAGMA user_version` は schema バージョン（現在 `2`）と一致し、`store_meta` に `schema_version` と `db_uuid` を保存します。読み取り専用の接続はジャーナルモードを切り替えません。切り替えはデータベースヘッダへの書き込みになるためです。
- schema バージョン 2: `root_dir`（データベースごとに束縛ルートはちょうど 1 つ）、`run`（実行ごとに 1 行。状態、基準世代と公開世代、網羅状態、件数）、`entry`（公開済み項目。ルートとパスが鍵）、`entry_stage`（実行中のステージング変更）、`entry_event`（変更イベント）、`change_export`（未出力の状態）。NULL は常に「取得できない、または該当しない」を意味し、0 や空文字の代用にはなりません。ディレクトリに `size_bytes` はなく、ダイジェストのない項目に `hash_sha256` はなく、プラットフォームが作成時刻を提供できない場合は `btime_utc` が NULL のままです。
- ステージングと公開: 走査は `entry_stage` だけに書き込みます。1 つの公開トランザクションがステージング行を `entry` へ移し、ステージングされた削除を適用し、変更イベントを書き込み、`root_dir.published_generation` を進め、実行を公開済みにします。したがって読み取り側は完全な世代か直前の世代しか見えず、途中の更新は見えません。公開トランザクションが失敗すれば全体がロールバックします。初回作成はコミットが成功するまで未公開（`published_generation` は NULL）のままで、中断された初回実行が完全な索引として扱われることはありません。部分的な走査は `coverage = partial` と記録された欠落を伴って公開できます。
- 書き込みロック: すべての書き込み経路は、書き込み用にデータベースを開く前にプロセス間ロック `<データベース>.evernightindex.lock` を取得します（`store.OpenTarget` は対応するロックのない書き込みオープンを拒否します）。OS のバイト範囲ロックなので、クラッシュ後もプロセスが終了すれば解放されます。待機は `--lock-timeout` に従い、キャンセルできます。ロックファイルは残り、記録された保持者情報は診断専用です。
- 実行の状態: 実行は `running` から `published`、`failed`、`interrupted`、`aborted` へ進みます。残った `running` 行は、次にロックを取得した実行が `abandoned` にします。公開時には開始時の世代と比較するため、その間に他者の結果で置き換えられていた場合は上書きせず拒否します（`E_PUBLISH_CONFLICT`）。
- トランザクション: `store.WithTx` は成功時にコミットし、それ以外は必ずロールバックするため、呼び出し側は「コミット済み」か「未コミット」のどちらかしか観測しません。キャンセルはドライバまで伝わります。
- 一貫性バックアップ: `store.Backup` は `VACUUM INTO` で対象ディレクトリの一時ファイルに書き出してから名前を変更します。WAL に残るデータを取りこぼす主ファイルの複製は行わず、既存の対象は上書きしません。
- 拒否: 他プログラムが作成したファイル、より新しい形式バージョン、未知または不完全な構造、破損したファイル、存在しないデータベース、ディレクトリを指定したパス、束縛ルートと一致しないルートには安定したエラーコード（`E_DATABASE_FOREIGN`、`E_DATABASE_VERSION_TOO_NEW`、`E_DATABASE_UNKNOWN_SCHEMA`、`E_DATABASE_CORRUPT`、`E_DATABASE_MISSING`、`E_DATABASE_IO`、`E_ROOT_MISMATCH`）を返し、何も上書きしません。
- 移行: 明示的に対応する旧バージョンのみ移行します（バージョン 1 から 2）。バージョン 1 のファイルに移行が知らない表がある場合は、再構築せず拒否します。

Windows amd64 で `go test ./internal/store ./internal/app ./internal/output ./internal/cli` により実測: WAL での作成、コミット、ロールバックの可視性、未コミットトランザクションを除外した一貫性スナップショット、バックアップの整合性検査、`PRAGMA integrity_check`、長い問い合わせの途中キャンセルとその後も使える接続、読み取り専用での書き込み拒否、公開前は不可視・公開後は可視になるステージング項目、公開トランザクション失敗時に直前の世代と項目が完全に残ること、世代の衝突、中断された初回作成が未公開のままであること、部分的な網羅と欠落の記録、変更イベントと未出力状態が索引と同じトランザクションでコミットされること、バージョン 1 からの移行でデータベース UUID が保たれること、外部・より新しい・未知・破損のデータベースの拒否、ルート不一致、そして別プロセスがロックを保持する場合の競合・タイムアウト・キャンセルと「保持プロセスの終了でロックが解放され、以前の索引が完全なまま整合性検査に通ること」。

## スキャンとメタデータ収集

走査とメタデータのモジュールは用意されテストもありますが、`index` コマンドはまだ接続していないため、このビルドでは以下の挙動をコマンドラインから実行できません。

- パスの出所は 1 か所だけです。明示的な相対パス（データベース、ログディレクトリ、一時ディレクトリ、ルート）はすべて、プロセス起動時に取得した呼び出し時の作業ディレクトリを基準に解決し、その後のプロセスの作業ディレクトリ、走査ルート、一時ディレクトリでは変わりません。ルートは絶対パスに変換しシンボリックリンクを 1 回だけ解決するため、同じディレクトリは常に同じ相対パスを生みます。
- 走査はルート自身、隠し項目、空のディレクトリ、到達可能なすべての子孫を記録します。ディレクトリの更新時刻が変わっていなくてもその部分木へ入ります。mtime が同じことは部分木が同じことの証明ではないためです。
- リンクは既定で追跡しません。シンボリックリンク、Windows のジャンクション、その他の再解析ポイントはそのオブジェクト自体として記録するため、循環もルート外へのアクセスも起こりません。ターゲット文字列は別に保存し、状態は `resolved`、`dangling`、`unreadable` のいずれかです。FIFO、ソケット、デバイスファイルはメタデータのみを読み、決して開かないため、書き込み側のいない FIFO でも走査が停止しません。
- 項目：型、サイズ（通常ファイルのみ）、Go のファイルモード、mtime と atime、プラットフォームが報告する作成時刻、メタデータ変更時刻、POSIX の uid/gid/デバイス番号/inode/ハードリンク数、Windows の属性ビット/ボリュームシリアル/64 ビットファイル ID/再解析ポイントタグ、macOS の BSD フラグ。Unix の `ctime` を作成時刻として保存することはなく、取得できない項目は 0 ではなく NULL のままです。

| プラットフォーム | 作成時刻 | 変更時刻 | その他の拡張 | 収集方法 |
| --- | --- | --- | --- | --- |
| Windows | 作成時刻 | `FILE_BASIC_INFO.ChangeTime` | 属性ビット、ボリュームシリアル、64 ビットファイル ID、再解析ポイントタグ、ハードリンク数 | `lstat` 1 回と、`FILE_READ_ATTRIBUTES` のみを要求するハンドル |
| macOS | `lstat` の birth time | `lstat` の ctime | BSD フラグ、uid/gid、デバイス番号、inode、ハードリンク数 | `lstat` 1 回のみ |
| Linux | `statx` の `STATX_BTIME` | `lstat` の ctime | uid/gid、デバイス番号、inode、ハードリンク数 | `lstat` と `statx` 1 回 |

- パス符号化は生のバイト列を保持します。相対パス、名前、比較キーはいずれも元のバイト列のままですが、表示とログ出力では制御文字と不正な UTF-8 バイトを `\xNN` にエスケープし、そのエスケープは可逆です。そのため空白や改行、先頭ハイフンを含む名前、Unix の非 UTF-8 名も損失なく区別できます。Windows のファイル名は改行を含められないため、この標本は他のプラットフォームでのみ検証します。
- ワイルドカードの意味は 1 か所で定義します。`/` と `\` はどちらも区切り文字で、エスケープ文字はありません。`*` は区切り以外の任意長、`?` はちょうど 1 文字、`[abc]`・`[a-z]`・`[!abc]` は文字クラスです。`**` はセグメント全体として現れる場合のみ 0 個以上のパスセグメントに一致します。先頭の `/` はルートへの固定、区切りを含まないパターンは任意深さの名前、末尾の `/` はディレクトリ限定を意味します。照合はデータベースに記録されたルートの大文字小文字ポリシーに従い、無効なパターンは `E_INVALID_PATTERN` で報告します。
- 除外の範囲は、明示的なパターン、本プログラムが生成するファイル（データベース、その `-journal`/`-wal`/`-shm` の補助ファイル、`<データベース>.evernightindex.lock` のロックファイル）、設定された変更ログディレクトリ、今回の実行専用の作業サブディレクトリです。これらの明示的なパスとディレクトリだけを除外するため、一時親ディレクトリにある無関係なユーザーファイルは通常どおり索引されます。
- 網羅の証拠は明示的に残します。ディレクトリの列挙成功、一部のみ成功、列挙失敗、項目の除外、ルートの失効はそれぞれ別のイベントとして表現し、欠落は相対パスの接頭辞一覧として記録します。後から「存在しない項目」を削除してよい根拠になるのは、列挙に成功したディレクトリだけです。除外された部分木、失敗した部分木、ファイルシステムをまたぐ部分木は決して根拠になりません。総数が不明な場合は割合を作りません。
- 並行数と中断は上限付きです。ディレクトリの列挙は最大 `max(1, 論理 CPU 数 / 2)` 個のワーカー（既定 1）と有界キューで動き、1 つの消費側が項目バッチを呼び出し元へ渡し、別の消費側がイベントを出力します。1 つの項目やディレクトリが読めなくても記録して走査を続け、中断時は新しい作業を止めて結果を不完全として報告します。
- 本ステップでは通常ファイルの内容を読みません。SHA256 を計算せず、ファイルデータも開きません。Windows のメタデータハンドルは属性権限のみを要求します。

走査・メタデータ・パターン照合のモジュールは実装済みでテストもありますが、`index` コマンドはまだ接続していません。未実装は次のとおりです。読み取り安定性検査付きのストリーミング SHA256、索引の作成と高速/詳細更新および保守的な削除判定、変更ログ CSV の書き出しと再試行、型付き条件・フィールド選択・JSONL/CSV/NUL 出力、`auto`/`metadata`/`sha256` の重複検出と現場再確認、一時作業コピーの公開と復旧。`info` は実装済みで、統計、実行ライフサイクル、ステージングと公開の境界、書き込みロックは揃っています。
